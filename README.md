# TAMYR POP — промо-платформа QURT

Мобильное веб-приложение для QR-перехода с упаковки, регистрации участника, безопасной активации кода, личного кабинета, уровней наград и администрирования кампании. Интерфейс KZ/RU, по умолчанию — KZ.

## Архитектура

- Next.js App Router + TypeScript + Tailwind CSS 4;
- PostgreSQL 16 и Prisma 6: нормализованные сущности участника, кампании, кодов, активаций, неизменяемой истории баллов, наград, согласий, сессий, аудита и notification outbox;
- коды хранятся только как HMAC-SHA-256, а открытый CSV появляется один раз в ответе на генерацию;
- `jose` подписывает httpOnly / sameSite cookie, сессия дополнительно сверяется с БД;
- Zod валидирует все публичные входы на сервере, а лимиты запросов хранятся в БД по HMAC-ключу;
- обработка одного промокода идёт в serializable-транзакции: условное обновление статуса + уникальное ограничение `promoCodeId` гарантируют однократные баллы и одного победителя при гонке запросов.

## Быстрый старт

1. Пошаговый порядок первого запуска
После клонирования или скачивания проекта выполните в терминале (в папке проекта) команды строго по порядку:

Bash
# Шаг 1. Установка всех библиотек и пакетов
npm install

# Шаг 2. Инициализация и первичная настройка (база данных / генерация типов)
npm run setup

# Шаг 3. Запуск локального сервера разработки
npm run dev

После успешного выполнения открывайте браузер: http://localhost:3000

2. Полный справочник ошибок и их решений
Ошибка 1: Запрет выполнения скриптов PowerShell
Как выглядит ошибка:

Plaintext
npm : Невозможно загрузить файл C:\Program Files\nodejs\npm.ps1, так как выполнение 
сценариев отключено в этой системе. Для получения дополнительных сведений см. 
about_Execution_Policies по адресу https:/go.microsoft.com/fwlink/?LinkID=135170.
+ CategoryInfo          : Ошибка безопасности: (:) [], PSSecurityException
+ FullyQualifiedErrorId : UnauthorizedAccess
Причина:

В ОС Windows по умолчанию включена политика безопасности, запрещающая запуск пользовательских сценариев PowerShell (включая исполняемые скрипты Node.js/npm).

Решение:

Выполните в терминале PowerShell команду:

PowerShell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
Нажмите Y (Да) или A (Да для всех) и нажмите Enter.

Повторите запуск вашей npm команды.

Ошибка 2: Отсутствие установленных зависимостей
Как выглядит ошибка:

Plaintext
"tsx" не является внутренней или внешней командой, исполняемой программой или пакетным файлом.
# ИЛИ
"next" не является внутренней или внешней командой, исполняемой программой или пакетным файлом.
Причина:

Вы пытаетесь запустить скрипт проекта (npm run setup или npm run dev), но папка с библиотеками node_modules отсутствует, так как зависимости ещё не были скачаны.

Решение:

Запустите полную установку пакетов, дождитесь завершения и только потом запускайте проект:

Bash
npm install
npm run setup
npm run dev
Ошибка 3: Проблемы с кешем npm / Сбои установки
Как выглядит ошибка:

Plaintext
npm ERR! code ERESOLVE
npm ERR! ERESOLVE unable to resolve dependency tree
# ИЛИ
npm ERR! code EACCES / ENOENT
Причина:

Конфликт версий установленных пакетов или повреждение локального кеша npm.

Решение:

Запустите установку с флагом принудительного согласования зависимостей:

Bash
npm install --legacy-peer-deps
Если проблема не ушла, очистите кеш npm:

Bash
npm cache clean --force
Ошибка 4: Занятый порт (Port 3000 in use)
Как выглядит ошибка:

Plaintext
Error: listen EADDRINUSE: address already in use :::3000
Причина:

Порт 3000 уже занят другим процессом Node.js или ранее запущенной копией проекта.

Решение:

Вариант А (Автоматический): Next.js сам предложит запустить проект на порту 3001 — нажмите Y.

Вариант Б (Освободить порт в Windows):

PowerShell
# Найти ID процесса на порту 3000
netstat -ano | findstr :3000
# Завершить процесс по его PID (замените <PID> на число из последней колонки)
taskkill /PID <PID> /F
Ошибка 5: Пропущены переменные окружения (.env)
Как выглядит ошибка:

Plaintext
Error: Missing environment variable NEXT_PUBLIC_DATABASE_URL
# ИЛИ сайт запускается, но выдает ошибку соединения с базой данных
Причина:

Для работы проекта требуются секретные ключи или адреса подключения, которые хранятся в локальном файле конфигурации.

Решение:

Найдите в корне проекта файл .env.example или .env.template.

Создайте его копию и переименуйте файл в .env (или .env.local).

Заполните необходимые значения (адреса БД, API-ключи).

## Переменные окружения

Скопируйте [`.env.example`](.env.example) в `.env` или дайте `setup` создать локальный вариант. В production задайте собственные значения не короче 32 символов для `CODE_HMAC_SECRET`, `SESSION_SECRET`, `OTP_HMAC_SECRET`, укажите production `DATABASE_URL`, отключите `ALLOW_DEV_OTP` и `DEMO_MODE`.

`ADMIN_PHONE` и `ADMIN_NAME` нужны только для первого администратора. Публичный домен не задан намеренно: перед релизом укажите согласованный URL в `NEXT_PUBLIC_APP_URL`, `sitemap.ts` и QR-команде.

## База данных и миграции

```bash
npm run db:generate
npm run db:deploy
npm run db:seed
```

Первичная миграция находится в `prisma/migrations`. Модель `PointLedger` append-only: начисления не редактируются. Конфигурация кампании хранит число баллов на код только на сервере; браузер не выбирает сумму.

Для бэкапа локальной БД:

```bash
docker compose exec -T postgres pg_dump -U tamyr tamyr_pop > tamyr_pop.sql
```

Восстановление выполняется только в подготовленную целевую БД: `psql -U tamyr -d tamyr_pop < tamyr_pop.sql`. Перед восстановлением подтвердите цель и создайте отдельный бэкап production.

## SMS и уведомления

Реальный SMS-провайдер не выдуман и не подключён. `OtpProvider` допускает только явно включённый `DevConsoleOtpProvider` вне production; без реального адаптера приложение отвечает `otp_provider_unconfigured` и не имитирует отправку.

`NotificationSchedule` и `NotificationLog` образуют outbox для будущего worker-а. Перед включением отправки реализуйте адаптер `NotificationProvider`, храните ключ провайдера только в env, подтвердите тексты KZ/RU и не планируйте маркетинговые сообщения без отдельного согласия.

## Команды качества

```bash
npm run lint
npm run typecheck
npm test
npm run test:integration
npm run test:e2e
npm run build
```

Юнит-тесты не требуют БД. `test:integration` использует реальный PostgreSQL с `TEST_DATABASE_URL`; при использовании Docker setup создайте отдельную БД `tamyr_pop_test`, примените миграции и передайте строку подключения. Playwright поднимает приложение через `npm run dev`; при первом запуске может потребоваться `npx playwright install`.

## Деплой

1. Выберите и утвердите домен, подключите HTTPS и установите `NEXT_PUBLIC_APP_URL`.
2. Разместите PostgreSQL и приложение в инфраструктуре, согласованной юристом для данных граждан РК; включите бэкапы, мониторинг, обновления и ротацию секретов.
3. В production отключите DEMO/dev OTP, подключите реального SMS-провайдера и worker outbox.
4. Выполните `npm run db:deploy`, затем `npm run build` и `npm start` за reverse proxy с TLS.
5. Сгенерируйте векторный QR после выбора домена по [инструкции](docs/qr-print.md) и выполните физический тест сканирования до тиража.

## Что проверить юристу перед запуском

Это не юридическая консультация и не заявление о соответствии. Проверить с юристом:

- итоговые правила акции, сроки, организатора, призы, лимиты и порядок выдачи;
- тексты согласия, политики, основания и срок хранения данных, процесс ответа на обращения и отзыва согласия;
- размещение базы и цифровых объектов на территории РК, а также условия трансграничной передачи, бэкапов и подрядчиков;
- достаточность набора полей и отдельного согласия на маркетинговые сообщения;
- договоры с SMS-провайдером, оператором/третьими лицами и меры защиты.

Актуальная редакция Закона РК «О персональных данных и их защите» предусматривает согласие, возможность его отзыва и хранение персональных данных в базе/цифровом объекте на территории РК; перед запуском сверяйте применимую редакцию и подзаконные правила на официальном ресурсе [ИПС «Әділет»](https://old.adilet.zan.kz/rus/docs/Z1300000094) и [правилах сбора и обработки](https://old.adilet.zan.kz/rus/docs/V2000021498).
